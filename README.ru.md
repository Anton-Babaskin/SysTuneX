## Зачем нужен SysTuneX?

Большинство инструментов для оптимизации Windows относятся к одной из двух категорий:

* оптимизаторы в один клик, которые не объясняют, что именно они изменили
* огромные коллекции реестровых твиков, скопированных из старых гайдов для геймеров

SysTuneX использует другой подход.

> **Сначала сохранить, потом изменить.**

Перед изменением реестра, службы Windows, DNS, схемы электропитания или параметров загрузки SysTuneX сохраняет реальное исходное состояние.

При откате восстанавливается **ваша предыдущая конфигурация**, а не придуманное приложением значение "по умолчанию".

Никаких недокументированных магических твиков. Никаких скрытых ошибок. Никаких обещаний, что одна и та же настройка поможет каждому компьютеру.

## Быстрый старт

### 1. Скачивание

Откройте:

**[GitHub Releases](https://github.com/Anton-Babaskin/SysTuneX/releases)**

Скачайте:

```text
SysTuneX.exe
```

SysTuneX публикуется как **самодостаточный win-x64 single-file executable**.

Устанавливать .NET отдельно не требуется.

### 2. Проверьте, что вы скачали

Рядом с исполняемым файлом в каждом релизе лежит `SHA256SUMS.txt`.

```powershell
Get-FileHash .\SysTuneX.exe -Algorithm SHA256
```

Это число должно совпасть с тем, что в `SHA256SUMS.txt`, — **и** с тем, что напечатано в открытом
логе сборки, которая этот файл создала. Почему вторая проверка и есть настоящая — в разделе
[Доверие и безопасность](#доверие-и-безопасность).

### 3. Запуск от имени администратора

SysTuneX запрашивает повышение прав при старте. Без них он не сможет сделать ничего: ключи реестра,
в которые он пишет, лежат в `HKEY_LOCAL_MACHINE`, смена типа запуска службы идёт через диспетчер
служб, а счётчику кадров нужна сессия трассировки. Все три отказывают обычному токену.

Windows SmartScreen выдаст предупреждение, потому что файл не подписан. Ниже — что именно означает
это предупреждение и как проверить файл самому, а не верить на слово.

## Доверие и безопасность

Вы собираетесь запустить **неподписанный исполняемый файл с правами администратора** на своей
машине. Это ровно тот случай, когда осторожность уместна, и «да всё нормально, доверьтесь» — не
ответ. Вот что можно проверить на самом деле.

### Почему нет подписи

Сертификат для подписи кода, который снимает предупреждение SmartScreen сразу, — это EV-сертификат:
несколько сотен долларов в год и привязка к зарегистрированной компании. SysTuneX — бесплатная
утилита без компании за спиной. Подпись имеет смысл и не исключена, просто её пока нет.

Стоит быть точным в том, что подпись доказывает, а что нет. Она подтверждает, что файл пришёл от
владельца сертификата и не изменялся после. О том, **безопасна ли программа**, она не говорит
ничего — подписанного вредоносного софта хватает. Проверки ниже дают больше, чем дала бы подпись.

### Цепочка, которую можно проверить

Исполняемый файл собирается не на чьём-то ноутбуке. Каждый релиз собирает GitHub Actions, публично,
из коммита, который вы можете прочитать:

1. Откройте [вкладку Actions](https://github.com/Anton-Babaskin/SysTuneX/actions) и найдите запуск
   для тега релиза.
2. Шаг **Checksum** печатает SHA-256 только что собранного файла — в лог, который задним числом
   никто не поправит.
3. Сравните его с результатом `Get-FileHash` и с `SHA256SUMS.txt`.

Если все три совпали, у вас на диске именно тот файл, который эта машина собрала из этого
исходника. Никто — включая того, кто владеет страницей релизов, — не сможет подменить бинарник так,
чтобы числа сошлись.

Можно и собрать самому и сравнить — см. [Сборка из исходного кода](#сборка-из-исходного-кода).

### Как пройти SmartScreen

Предупреждение говорит «Система Windows защитила ваш компьютер» и прячет кнопку запуска за ссылкой.
Так происходит с любым исполняемым файлом без наработанной репутации — это утверждение о том,
**сколько людей его запускали**, а не о том, что он делает.

**Подробнее → Выполнить в любом случае.** Если не хочется — сначала сверьте контрольную сумму или
загрузите файл на [VirusTotal](https://www.virustotal.com/) и посмотрите, что скажут семьдесят
антивирусных движков.

### Что именно происходит с машиной

Каждое изменение **записывается в журнал до того, как будет сделано**, и отменяется из журнала
изменений — это правило, вокруг которого построен весь код, и на него есть тесты, которые падают
при его нарушении. Конкретно приложение пишет:

| Что | Куда | Откат |
| --- | ---- | ----- |
| Твики | Значения реестра в `HKLM` и `HKCU` | Прежнее значение восстанавливается точно, а отсутствовавшее — удаляется |
| Службы | Тип запуска через диспетчер служб | Исходный тип запуска и состояние восстанавливаются |
| Питание | Активная схема электропитания | Прежняя схема возвращается |
| Сеть | DNS-серверы, файл hosts | Возвращаются прежние серверы или DHCP; записи из hosts удаляются |
| Очистка | Временные файлы, кэши, дампы | **Не откатывается** — файлы удаляются, и приложение предупреждает об этом заранее |

Драйвер, службу или фоновый агент он **не** устанавливает. Никуда не звонит: телеметрии нет, сетевых
запросов нет вообще, кроме теста задержки DNS, который вы запускаете сами. После закрытия ничего не
остаётся работать, кроме значка в трее, если вы его включили.

### Если хочется сначала почитать код

Ради этого он и открыт. Что смотреть в первую очередь: `TweakEngine` — как изменение попадает в
журнал до записи, `BackupService` — что в этом журнале лежит, и каталоги в
`src/SysTuneX.Core/Tweaks/` — каждое значение реестра, которого приложение когда-либо коснётся.
Скрытого списка нет.

Об уязвимостях сообщайте приватно по [SECURITY.md](SECURITY.md), а не в публичном issue.

## Игровой режим

Один переключатель на главной. Останавливает фоновые службы, помеченные каталогом как безопасные, поднимает схему питания и освобождает память.

Это намеренно **не** «профиль под другим названием». Профиль пишет в реестр значения, которые переживают перезагрузку и откатываются через журнал. Игровой режим делает только то, что отменяется мгновенно: службы **останавливаются, а не отключаются** — тип запуска не трогается, следующая загрузка ровно такая же, — а прежняя схема питания записывается и возвращается. Ничего из этого не требует перезагрузки, поэтому выключение действительно возвращает машину, а не оставляет её наполовину затюненной.

Сессия пишется на диск, поэтому прерванную всё равно можно выключить и восстановить, а не бросить десяток остановленных служб.

### Может следовать за игрой

Включите автоматический игровой режим — SysTuneX следит за запуском игры. Двадцать пять игр распознаются из коробки, любая другая добавляется одним полем: именем исполняемого файла.

### Или за часами

Расписание держит режим включённым в заданное окно дня, при желании — только по выбранным дням. Оно сверяется с часами раз в минуту, а не ставится таймерами на края окна: таймер промахивается, если машина в этот момент спала, а промазанный край оставил бы режим включённым. Окно, которое заканчивается раньше, чем началось, идёт через полночь и принадлежит дню, в котором началось.

**Ни то ни другое не отменяет включённое вручную.** Режим, включённый вами в 23:05, переживёт расписание, закончившееся в 23:00, а выход из игры не завершит сессию, которую начали вы.

Автоматика работает только пока открыт SysTuneX. Делать это при закрытом приложении означало бы службу Windows, а фоновой службе, которая останавливает другие службы, доверия нужно куда больше.

## Частота кадров

SysTuneX считает кадры через **трассировку событий Windows (ETW)**, читая события Present, которые графический стек DirectX и так записывает, — тот же источник, что у PresentMon и счётчика Xbox Game Bar.

**В процесс игры ничего не внедряется.** RTSS, Afterburner и Fraps перехватывают графический API изнутри процесса игры; так они рисуют оверлей, и ровно это ищет античит. Утилита, которую ставят именно перед игрой, не может позволить себе риск бана.

Плата за это названа, а не спрятана: **оверлея над полноэкранной игрой нет**. Чтобы посмотреть цифры, переключитесь на страницу «Монитор». Счётчик намеренно остаётся на игре, когда на переднем плане оказывается сам SysTuneX: перевести его на своё окно значило бы показывать частоту кадров SysTuneX, а это хуже, чем ничего.

Рядом со средним значением показан **1% низких** — частота кадров худшего процента кадров. Среднее 144 при 1% низких в 40 заикается, а стабильные 90 — нет; одно среднее прячет ровно ту проблему, ради которой эта утилита и существует.

Счётчик включается переключателем, а не сам собой: сессия трассировки — общесистемный ресурс, поэтому она работает, когда её попросили, и закрывается при выключении. Для запуска нужны права администратора; если сессия не стартовала, страница пишет об этом, а не показывает пустое число.

## Температуры

Температура видеокарты берётся из библиотеки её же производителя — она идёт с драйвером, ставить ничего не нужно: **NVML** у NVIDIA (температура, загрузка, вентилятор) и **ADL** у AMD (температура и вентилятор). Температура процессора — из **зоны ACPI**, если её отдаёт прошивка; это зона на плате, а не кристалл процессора, и на главной так и написано.

Из ADL используются только скалярные вызовы. Богатые принимают большие структуры, раскладка которых отличается между ветками драйвера, и ошибка в ней не возвращает код ошибки, а портит память: утилита, способная уронить машину, которую настраивает, хуже утилиты, которая не показывает температуру. Видеокарты Intel пока не поддержаны.

**SysTuneX не ставит драйвер уровня ядра и не будет.** Чтобы честно читать температуру кристалла, нужен ring-0 помощник, а готовые входят в список уязвимых драйверов Microsoft и вызывают срабатывание античитов. Для утилиты, которую ставят ради игр, это плохой размен.

Поэтому показание появляется, только если датчик реально ответил. Если не ответил ни один — карточка говорит об этом и объясняет почему: отсутствие показания это не ноль градусов. Значения вне того, что выдаёт работающая железка, тоже отбрасываются: часть прошивок возвращает заглушку, а правдоподобное неверное число хуже пустоты.

## До и после

Запишите состояние машины до изменения и после, затем сравните. В результате перечислено, какие твики стали применёнными, какие службы запустились или остановились и сменилась ли схема питания.

**Это не измерение производительности и не притворяется им.** Здесь сравнивается конфигурация, а не скорость: за временем кадра смотрите на страницу «Монитор» во время игры или прогоните один и тот же бенчмарк с обеих сторон и сравните сами. Память и число процессов показываются, только если сдвинулись сильнее, чем дрейфуют сами по себе: выдать разницу в 3 МБ за эффект твика — это ложь в форме данных.

## Безопасность

SysTuneX изначально проектируется вокруг обратимости и прозрачности.

### Сначала сохранить

Предыдущее состояние записывается до изменения системы.

### Точный откат

Если параметр реестра существовал до запуска SysTuneX, восстанавливается его исходное значение.

Если параметра до этого не существовало, при откате он удаляется вместо записи придуманного значения.

### Уровни риска

Твики разделены по уровню риска.

Advanced-настройки требуют отдельного подтверждения и заранее описывают возможные последствия.

### Учёт версии Windows

Настройки, относящиеся к определённым функциям Windows 11, предлагаются только там, где эти функции действительно существуют.

### Настоящие ошибки

Ошибки записи в реестр, изменения служб или выполнения системных команд отображаются как ошибки, а не как успешная операция.

### Прозрачная очистка

Перед удалением SysTuneX определяет целевые пути, количество файлов и их общий размер.

## Журнал изменений

Журнал отката хранится здесь:

```text
%ProgramData%\SysTuneX\backup.json
```

Он содержит состояние, необходимое для восстановления поддерживаемых изменений:

* значения реестра
* конфигурацию служб Windows
* DNS
* настройки электропитания
* параметры загрузки

На странице Change Log можно восстановить отдельные изменения или откатить всю записанную конфигурацию.

Журнал также можно экспортировать в JSON.

## Логи и диагностика

Логи приложения находятся здесь:

```text
%ProgramData%\SysTuneX\logs
```

SysTuneX создаёт отдельный лог за каждый день и хранит их семь дней.

Сообщения, отображаемые пользователю в интерфейсе, также записываются в лог, поэтому UI и диагностическая информация описывают одно и то же событие.

Режим **Verbose logging** дополнительно записывает чтение реестра и выполняемые системные команды.

Функция **Build a report** собирает полезную для диагностики информацию:

* версию и редакцию Windows
* аппаратную конфигурацию
* состояние elevation
* журнал изменений
* последние записи логов

Ошибки запуска дополнительно записываются в:

```text
%ProgramData%\SysTuneX\errors.log
```

## CI

Каждый push и pull request проверяется на Windows runner в GitHub Actions.

Pipeline:

```text
Restore
   ↓
Build
   ↓
Core tests
   ↓
WPF startup tests
   ↓
Publish win-x64
   ↓
SHA256 checksum
   ↓
Release artifact
```

WPF startup tests создают реальный экземпляр приложения, загружают его ресурсы и создают основное окно и страницы.

Это позволяет обнаруживать runtime-ошибки XAML, которые обычная успешная компиляция не показывает.

---

### Выпуск релиза

Релизы публикуются только из основной ветки. Релиз, собранный из рабочей ветки, описывал бы код,
который никто не влил, и оставил бы тег на коммите, который может никогда не попасть в `main`.

1. Добавьте секцию `## vX.Y.Z` в начало [`CHANGELOG.md`](CHANGELOG.md).
2. Пропишите ту же версию в `release.version`.
3. Влейте в `main`.

Дальше CI соберёт, прогонит тесты, опубликует `SysTuneX.exe` и `SHA256SUMS.txt` и создаст релиз,
в теле которого будет **только секция этой версии** плюс общий футер.

Версия с суффиксом — `v2.5.0-rc1` — помечается как предварительная, обычная `v2.5.0` — нет.
Повторный запуск на неизменённой версии только обновит вложения, так что это безопасно.

## Сборка из исходного кода

Требования:

* .NET 10 SDK
* Windows для полного набора WPF-тестов

Клонирование:

```powershell
git clone https://github.com/Anton-Babaskin/SysTuneX.git
cd SysTuneX
```

Restore и build:

```powershell
dotnet restore
dotnet build
```

Core tests:

```powershell
dotnet test tests/SysTuneX.Core.Tests/SysTuneX.Core.Tests.csproj
```

Запустить тесты запуска. Им нужен настоящий WPF, поэтому что-то делают они только под Windows:

```powershell
dotnet test tests/SysTuneX.App.Tests/SysTuneX.App.Tests.csproj
```

```powershell
dotnet publish src/SysTuneX.App/SysTuneX.App.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -p:PublishReadyToRun=true
```

## Проверка производительности

SysTuneX меняет системную конфигурацию. Он **не обещает конкретное увеличение FPS**.

Чтобы определить, помогла ли конкретная конфигурация вашему компьютеру, сравнивайте одинаковую нагрузку до и после по таким метрикам:

* average FPS
* 1% и 0.1% lows
* стабильность frame time
* input latency
* DPC / ISR latency
* загрузка CPU и памяти
* network latency и packet loss

Используйте одну и ту же игровую сцену, графические настройки и продолжительность теста.
